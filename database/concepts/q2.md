# Question 2

What specific PostgreSQL indexing strategies, such as BRIN or partial indexes, do you use to optimize query performance on massive, append-only audit logs?

## Summary
Audit logs are usually huge and mostly only get new rows added. Adding normal B-Tree indexes on every field makes inserts slower and can use too much memory. A better approach is to use BRIN for time-based queries and partial indexes for only the important rows.

## What this means
- Audit logs are append-only: new rows are written but old rows are rarely changed.
- Because rows are added in time order, a time index can be very efficient.
- Most queries are about recent data or rare events like errors.
- Full indexes on every column make the database do too much work on each insert.

## Why BRIN is useful
A BRIN index keeps a small summary for each block of pages instead of indexing every row.

That works well when:
- the data is stored in order by time,
- queries use a recent time range,
- and you want a very small index.

A BRIN index is not for exact lookups, but it is great for skipping old data quickly.

## Why partial indexes are useful
Most audit rows are normal events. If you only care about errors, you do not need an index for every row.

A partial index only includes the rows you care about, such as:
- `severity = 'ERROR'`
- `event_type = 'LOGIN_FAILED'`
- `tenant_id = ... AND severity = 'ERROR'`

This keeps the index small and fast.

## Example
```sql
CREATE TABLE audit_logs (
    id BIGSERIAL PRIMARY KEY,
    created_at TIMESTAMPTZ NOT NULL DEFAULT NOW(),
    tenant_id UUID NOT NULL,
    severity VARCHAR(10) NOT NULL,
    event_type VARCHAR(50) NOT NULL,
    payload JSONB
);

CREATE INDEX idx_audit_logs_created_at_brin
    ON audit_logs USING BRIN (created_at);

CREATE INDEX idx_audit_logs_errors
    ON audit_logs (event_type, tenant_id)
    WHERE severity = 'ERROR';
```

### How a query uses this
For a query like:

```sql
SELECT *
FROM audit_logs
WHERE created_at >= now() - interval '7 days'
  AND severity = 'ERROR'
  AND event_type = 'LOGIN_FAILED';
```

- The BRIN index narrows the time range.
- The partial index helps find only the error rows.
- Together, they avoid scanning the whole table.

## Trade-offs
- **BRIN:** very small index and fast for time ranges, but not good for exact matches.
- **Partial index:** small and fast for rare rows, but only works when the query matches the filter.
- **Full B-Tree:** useful for exact lookups, but can become too large and slow down inserts on huge audit logs.

# Question 3

How do you identify and mitigate PostgreSQL transaction ID (TXID) wraparound in a database handling thousands of operations per second?

## Summary
TXID wraparound happens when PostgreSQL assigns more transaction IDs than it can safely track. In high-write systems, this can happen quickly if autovacuum falls behind. The solution is to monitor the wraparound age and keep vacuum aggressive so old rows are frozen before they become dangerous.

## Problem
PostgreSQL uses 32-bit transaction IDs (TXIDs), which wrap around after about 4 billion transactions. If the database reuses old TXIDs without freezing old rows, it can mistake old data for new or delete live rows unexpectedly. This is a severe risk on systems with thousands of operations per second.

## Solution
- Monitor `age(datfrozenxid)` and `age(txid_current())` in `pg_stat_database`.
- Keep autovacuum tuned so it freezes old rows in time.
- Use `VACUUM` or `VACUUM FREEZE` on busy tables before they reach the danger zone.
- In extreme cases, use `VACUUM FREEZE` manually or tune `autovacuum_freeze_max_age` lower than the default.

## Key Concepts
- **TXID wraparound:** PostgreSQL transaction IDs are 32-bit and will wrap after ~4 billion values.
- **Frozen tuples:** When a row is frozen, it no longer needs a current TXID to be visible.
- **Autovacuum:** The main process that prevents wraparound by freezing old row versions.
- **`datfrozenxid`:** The oldest TXID that still needs to be frozen in a database.
- **`autovacuum_freeze_max_age`:** The setting that decides when autovacuum should aggressively freeze rows.

## Example
```sql
SELECT datname, age(datfrozenxid) AS frozen_age
FROM pg_database;

SELECT relname,
       age(relfrozenxid) AS frozen_age,
       n_dead_tup,
       n_live_tup
FROM pg_stat_all_tables
WHERE relname = 'transaction_events';
```
- If `age(datfrozenxid)` is above 1 billion, autovacuum needs to run aggressively.
- If `age(relfrozenxid)` is close to `autovacuum_freeze_max_age`, schedule a manual `VACUUM FREEZE`.

## Trade-offs
- **Aggressive autovacuum:** safer for wraparound, but it consumes CPU and I/O.
- **Manual vacuum:** gives control, but it can cause extra load if run too often.
- **Lower freeze age:** reduces risk, but increases autovacuum frequency.
